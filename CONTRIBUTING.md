# Contribuição

Alterações devem apresentar problema reproduzível, comportamento resultante, impacto de compatibilidade, versão e evidências de validação. Preserve os avisos legais e registre dependências incorporadas.

Utilize uma branch própria e abra uma pull request. A branch principal exige as verificações automatizadas configuradas, histórico linear e resolução de discussões. Não inclua bancos de dados, backups, configurações de instalações, chaves, tokens, dados pessoais ou capturas contendo informações reservadas.

Execute as verificações documentadas no README e teste os fluxos afetados em WordPress isolado. Mudanças em arquivamento, SQL, extração, criptografia, permissões ou recuperação exigem testes de sucesso e falha proporcionais ao impacto. Atualize o CHANGELOG e a documentação operacional.

Cada pacote deve possuir versão própria, commit identificado, etiqueta anotada, notas de versão, ZIP e SHA256SUMS. Versões já publicadas não devem ser substituídas por conteúdo diferente. Adota-se MAJOR.MINOR.PATCH.
